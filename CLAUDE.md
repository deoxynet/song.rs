# ggwave-voice

Voice-formant acoustic modem. Encodes data as vowel-like audio that survives phone codecs and noise cancellation.

## Build & Test

```bash
cargo build
cargo test                   # unit + integration tests
cargo test --test robustness # channel simulation tests (phone, AM radio, etc.)
cargo test --test opus        # real libopus roundtrip (needs system libopus)
cargo bench                  # criterion benchmarks (encode/decode/roundtrip)
```

## Architecture

| Module | Purpose |
|---|---|
| `src/lib.rs` | Public API (`encode`, `Decoder`), top-level tests |
| `src/protocol.rs` | Constants (sample rate, symbol timing, FFT size, formant bands) |
| `src/formant.rs` | Vowel alphabet, melodic synthesis, F0-agnostic detection, 2-bit packing |
| `src/encoder.rs` | Payload → RS-encode → symbols → synthesized audio |
| `src/decoder.rs` | Streaming state machine (Listening → Receiving → Analyzing) |
| `src/fft.rs` | FFT wrapper (Hann-windowed and raw power spectrum) |
| `src/reed_solomon.rs` | RS codec over GF(2^8) with erasure support, ported from ggwave C++ |
| `src/phy.rs` | PHY layer: stop-and-wait ARQ, fragmentation (up to 2,224 bytes), ACK/NAK, timeout/retransmit |
| `src/dss.rs` | Direct Sequence Spread (XOR whitening, currently unused) |
| `src/transfer.rs` | Secret-transfer profile: CRC-32 gate, paranoid ECC, repeat + soft combining (`TransferRx`) |

## Key Design

- **Echo/clock spectral retry**: a stable non-nominal guard grid may reuse cached FFT bins for one frequency-normalized F2-template retry. Estimate rate from two agreeing halves, excluding initial sync; leave raw spectra, input samples, and timing starts untouched. Copy already-cached bins and lazily transform only missing windows. Require a locally verified header or the full corrected preamble/pilot; never override a conflicting supplied length. CRC or an explicit validator is mandatory, including for unknown-length recovery. Successful observations contain exactly the measured codeword, and its endpoint remains on the original grid. Failed attempts do not mutate receiver buffers, hints, or combining observations.
- **Echo-obscured timing**: `envelope_clock_period` correlates a 3 ms-smoothed power envelope at 0.5 ms resolution. An eight-slot coarse estimate constrains a 24-slot refinement independently in each recording half; require correlation, bounded non-nominal rate, and half agreement. A qualifying estimate adds at most 32 phase hypotheses over the first two nominal recording slots after the original priority hint and before all unchanged nominal/guard searches. This is a timing hypothesis, never sync or length evidence. Unchecked profiles skip it. Uniform-grid steps remain within the existing ±2.5 ms radius and leave complete 50 ms voice windows before the next boundary. Tests cover rate/gain bounds, rejected noise/DC/nominal/changing clocks, cache/sample/endpoint identity, invalid CRC with valid RS parity, validator rejection, unread suffixes, subsequent melodies, and both sample rates. Browser echo checks use real production workers/WASM; measure native callback cost with `receiver_latency -- --echo` or `-- --transfer --echo`.
- **Vowel-only encoding**: each symbol carries 2 bits via vowel identity (F2 formant, 4 vowels). Pitch carries no data; the receiver does not need to know the melody. Pitch still affects harmonic spacing and channel margin.
- **Default melody: Giant Steps.** `encode()` sings the 16-bar head (`protocol::GIANT_STEPS`) in the B2–F#4 register, one note per payload byte. Current block sync/header sing The Lick (`protocol::FRAMING_LICK`): E–F#–G–A–F#–D–E, the relative-minor voicing of the opening Gmaj7; the intro region is exactly one 24-slot phrase, so the pilot calibration reference never changes. The CRC/parity/outro sings Coltrane's actual solo (`protocol::GIANT_STEPS_SOLO`, 512 slots = two choruses): a MIDI transcription of the 1959 recording quantized to its own eighth-note grid, two 60 ms slots per eighth (~250 bpm), transposed −4 semitones (≡ the head's −16 mod 12, key-true) and octave-folded into B2–F#4. `protocol::outro_f0` indexes it modulo the table, with two carve-outs. (1) The final `PREAMBLE_LEN` slots: the end preamble is a sync marker and holds the home E3 (`FRAMING_LICK[0]`), never the melody. (2) Outros under `SOLO_MIN_OUTRO_SLOTS` (44 slots / 11 bytes) play The Lick transposed through the Coltrane cycle (`FRAMING_LICK_CYCLE`: Em over G → Cm over E♭ up a minor sixth → G♯m over B up a major third, all inside B2–F#4; incomplete tails hold home E). The OUTRO starts the cycle at phrase index 1 (Cm over E♭) because the intro already played home and Standard short outros are exactly 36 slots — one phrase plus the held-E tail — so a home-key outro would never leave Em and the changes would be unreachable (frame geometry: Standard outros are 36 or ≥44 slots, nothing between). With the offset every jingle modulates G → E♭ across the frame, and a 1-byte Paranoid outro (40 slots) reaches G♯m. The per-phrase 24-slot rhythm is identical across transpositions, which is what the short-echo ladder correlates on (measured: cycle passes the same 8 kHz gate the solo failed); the intro region is exactly one phrase, so the pilot always keeps the home Em voicing, and held-E tails keep the end-marker pitch stable: measured at 8 kHz, a 4-byte frame's varied solo slots defeat every short-echo clock fallback rung (`short_echo_clock_estimates_preserve_gates_and_recover_frames`) because the halves keep too few repeated slots; the periodic Lick passes. 44 is the measured minimal bound — a 76-slot version broke the tuned 48 kHz next-melody echo tails, and 11+-byte solo outros pass the full echo matrix at both rates. This is load-bearing, not styling — the damaged-header 140-byte/volume-10/40 dB-tilt Opus case (`opus_continuous_call_damaged_header_after_idle`) sits at the recovery margin and fails if the end marker's pitch follows the tune (measured: register folds to B♭3 did NOT fix it; pinning the end preamble did, at full register). Frame timing is unchanged. `encode_armored()` and the transfer profile retain the D lydian arpeggio for their payload. Explicit Legacy framing retains the old arpeggio throughout. Pilot EQ references are profile-specific. Streaming FEC retains its original arpeggio pitch schedule; its independent CRC framing is described below. The broader register passes the all-vowel spectral-tilt + RNNoise sweep; older observations that this channel necessarily destroys the melody predate the narrower formants and framing fixes.
- **Vowel shape and register**: F2 Gaussian sigma is 180 Hz. This separates neighboring vowels after tilt and denoising while retaining pitch, vibrato, accents, and timing. Tests cover every chromatic note B2–F#4 with every vowel, quiet phrases, detuned pitches, and changing melody contours. Default classification retains `EXPECTED_F2_CENTROIDS`; template and F0-adaptive retries derive expectations from the current synthesis model.
- **Symbol envelope and timbre**: raised-cosine ramps are FIXED at 10 ms attack / 8 ms release — they are the streaming clock tracker's signal, not styling. Its guard probes read energy within ~2.5 ms of both boundaries: a 13 ms attack fails positive-offset correction detection and a 10 ms release fails the negative side (`stream_clock_corrections_are_bounded_directional_and_scale_independent`); 16/13 additionally fails the marginal damaged-header Opus case on ramp energy. Harmonic phases must stay zero-aligned: Schroeder dispersal sounds smoother but weakens the pitch-rate envelope structure `envelope_clock_period` correlates on (fails `echo_clock_recovery_preserves_the_next_melody`). The 10 ms silent guard remains untouchable (RNNoise speech classification depends on the rhythmic gaps). `VIBRATO_DEPTH` 0.006→0.004 and `HF_ROLLOFF_RATE` 600→450 passed the matrix but were reverted as audibly indistinguishable — the synthesis is at its original voicing, and further timbre work should target melody/accents, not the waveform.
- **Symbol timing**: 50 ms voiced + 10 ms guard = 60 ms per symbol (2880 samples at 48 kHz)
- **Preamble**: 4 symbols start ([0, 3, 0, 3]) and end ([3, 0, 3, 0]), using max-distance vowel pair
- **Streaming codec**: RS(15,k) over GF(2^4), one GF(16) symbol = two vowel symbols, byte = 2 nibbles = 4 vowels (no bit straddling). End-of-stream requires four unvoiced windows ~10 dB below running RMS; voiced periodicity protects quiet phrases. Never use a vowel pattern as the end marker, since data can alias it.
- **Default block-frame integrity**: Standard appends IEEE CRC-32 (little-endian) to the caller's payload before RS encoding; the 3-byte header still advertises caller-visible length. CRC is verified inside each hard/erasure/Chase attempt, before deciding whether to continue the retry ladder. The payload's waveform is unchanged; checksum/parity only extend the musical outro. A regression covers a hard-RS miscorrection rejected by CRC followed by successful erasure recovery.
- **RS ECC**: adaptive — `len < 4 ? 2 : max(4, 2*(len/5))` parity bytes, with `len = payload + 4` for Standard. Use `EccProfile::encoded_bytes` for wire geometry. Payload limit remains 140 bytes. `EccProfile::Legacy` explicitly selects pre-CRC block framing; there is no automatic downgrade. The transfer format is unchanged; PHY adopts the new default. Streaming uses a separate `StreamProfile`.
- **Decoder**: streaming, processes symbol-sized windows. History ring buffer for alignment recovery. Multi-offset analysis as fallback. RS erasure decoding via symbol confidence as fallback when hard-decision fails.
- **Block clock retries**: pair failed ordinary alignments with at most 32 frame-anchored variable-rate hypotheses. `audio::guard_clock_evidence` shares StreamRx's measurement algorithm, distinguishing clear guards from missing timing evidence. Block grids hold the measured period through obscured guards as well as silence; StreamRx retains its original nominal fallback for voiced windows. Only an intact supported header or complete preamble/pilot match can seed a grid. Keep the lowest guard/voice energy score per nominal-slot bucket among queued candidates, capped at 32. Trying successive phases separately avoids choosing a denoiser tail as the only clock hypothesis. Nominal and clock-grid length locks are separate; each clock retry inherits only its physical frame's supported length. Nominal start hints cannot index a variable-rate grid. Reuse all classifiers, CRC/validator gates, and one FFT per actual voiced window. Recording limits and a second validated completion probe include `clock_slack_windows`; failed probes resume sliding header scans without discarding future probes. An exact header-derived endpoint also permits CRC/validator-checked clock recovery amid trailing voiced background, never unchecked Legacy prefix delivery. Stop clock retries after verified recovery; no synthesis or wire-format changes, and no clock grids after ordinary success.
- **Melody-derived length hint**: the framing melody after the payload is deterministic per profile, so the solo's start position is structural length evidence (`decoder::melody_length_hint`, fed by `formant::note_match_scores` per-window template rows cached in `AlignedSpectra`). Computed in final analysis only when no length lock exists and the profile is checked (Standard CRC or a caller validator); it becomes ONE prioritized candidate right after real header evidence inside `decode_symbols_once`, and may decode as a gated prefix of a region longer than the ordinary 3-byte trailing slop (damaged header + trailing voiced background — the lab-proven case). Never a length lock, never outranks a header, never delivers without CRC/validator, and Legacy (one arpeggio throughout, no melody transition) is fully excluded. Wrong hints cost one extra gated RS trial and cannot change intact-frame decoding. Feasibility: `examples/melody_parity_lab.rs` — exact length on 70/70 hostile-channel cases including 137/200 corrupt bytes; the same lab killed melody-mismatch RS-erasure flags (5–10% recall: pitch survives what flips vowels, so confidence already dominates). Tests cover default/custom melodies × both checked profiles × noise, Legacy exclusion, symbol-domain rescue vs. proven no-hint failure, wrong-hint harmlessness, and end-to-end delivery with a destroyed header before trailing voiced background.
- **Cross-phase header reuse**: the phased sliding scan retains its intact, sync-supported lengths in `frame_length_hints`, keyed by nominal physical start slot. Repeated evidence at one start must agree; conflicts stay `None` until reset. A common unambiguous length among current candidates can supply the existing trial/nominal length lock. Each candidate overrides that common lock with its own frame's hint; clock hypotheses inherit only their physical frame's supported length. This avoids repeated speculative-length RS/Chase work when a header was readable at a different phase. Hints are bounded by the recording's start positions and cleared at reacquisition/rollover. Sync-only scans never invent a length, and every delivery retains its original CRC/validator gates. Tests cover incomplete slow/fast-clock transfers, candidate-local evidence, conflicts, resets, damaged headers, and a bad-CRC frame followed by a different-length sender.
- **Clock-retry performance regression**: `web/tests/browser-smoke.mjs` runs 64/120-byte transfers at ratios 0.98/1.02 independently after the existing worker/UI checks. All four now pass the unchanged 60-second queue-drain limit in Chrome 153; the formerly timing-out 120-byte 0.98 case now takes a few seconds. Reproduce native workloads with `cargo run --release --example receiver_latency -- --transfer --clock`. Long callbacks remain, so passing these desktop checks is not a hard real-time or physical-device guarantee.
- **Audio input boundary**: `audio::append_finite_samples` is shared by block `Decoder` and `StreamRx`; TransferRx/WASM and PHY inherit it through Decoder. Replace only NaN/infinities with zero before buffering so invalid capture values cannot poison RMS/noise-floor state or FFTs. Preserve every sample position and every finite sample's bits, including signed zero, subnormals, and finite values outside ±1. Do not discard a callback or reset the receiver for a sparse invalid sample. Tests reproduce both state-poisoning failures and cover all-note/vowel and detuned recovery, callback fragmentation, consecutive streams, and ACK timing.
- **Expressive pitch API**: `encode_with_pitch` accepts a per-payload-byte F0 track in the B2–F#4 compass. The entire chromatic register is covered by six channel sweeps; it is not restricted to the armored arpeggio. Every block profile checks track length and rejects nonfinite/nonpositive values with `Error::InvalidPitch { index, hz }` before RS allocation or synthesis, including at zero volume. Do not retune, clamp, or replace valid values. Positive pitches outside the tested register are not a channel guarantee. Tests check exact error index/value bits, validation order, and sample-exact payload slots at all chromatic notes × ±30/0 cents in all profiles and volumes 0/50/100, plus clean round trips.
- **Transfer input validation**: reject empty caller payloads before appending CRC; four checksum bytes alone cannot meet the receiver's nonempty-payload gate. Both direct/repeated encoders return the existing `EmptyPayload` error. The real-browser test checks both WASM exports throw recoverable JS errors and that a subsequent one-byte payload containing zero still produces identical single/repeated-copy audio.
- **StreamTx chunk invariance**: `feed_raw` chunks and `emit` callback boundaries preserve the exact single-feed waveform in both profiles, even when sync is emitted before input and between raw chunks. Tests cover empty calls, starvation versus finished state, idempotent finish, parity extremes, interleaver padding, maximum payload, and exact decoded bytes. This does not make playback underruns safe: callers must buffer enough input for continuous playback. `feed` remains a one-payload API.
- **Browser receiver**: `web/js/receiver-worker.js` hosts the unchanged synchronous WASM decoder in a classic worker; `receiver.js` transports copied ≤2048-sample packets with one in flight, FIFO acknowledgements, and a 120-second queued/in-flight sample bound. Overflow/worker failure stops capture visibly; never silently drop samples or fall back to main-thread decoding. Clear and local-TX pause/resume increment the session generation; stale responses cannot restore cleared results. Verified delivery preserves queued audio and lets the UI latch separately. `AudioEngine` cancels late permission/worklet continuations and stops their tracks. `node web/build.mjs` builds both `web/pkg` (web bindings) and `web/pkg-worker` (no-modules bindings). `npm --prefix web test` covers transport/capture; `npm --prefix web run test:browser` uses isolated Chrome, synthetic audio/fake mic, real workers/WASM, sequential deliveries, result latching/clear, failure/retry, and a main-thread heartbeat during periodic-background recovery. No physical-device or hard real-time guarantee.
- **Calibration pilot**: 8 known symbols after the start preamble; the receiver measures each vowel's F2 centroid through the live channel. Measured centers are used strictly as a decode RETRY after the default centers fail (sanity-gated: ascending, ≥120 Hz apart, within ±150 Hz of defaults) — never as primary, because a pilot measured through a denoiser's warm-up ramp can pass the gate yet be worse. Block path only.
- **Channel EQ + template retry ladder** (block path): the pilot yields an F2-band channel power-gain estimate (`formant::estimate_eq`, log-domain buckets, inverse limited to 60 dB using power units: 10*log10). Retries use calibrated centers, EQ centroids, templates, F0-adaptive centroids, and their ensemble. A synthetic 50 dB power-tilt test verifies the inversion range; the extreme-channel test allows failure but rejects incorrect payloads.
- **Structural preamble detection**: exact vowel matching fails under tilt, but the preamble's lo-hi-lo-hi centroid *alternation* survives any monotone spectral shaping (`structural_start_match`, swing ≥250 Hz, spread <200 Hz). The Listening lock accepts either; a late lock is covered by a 16-window history ring. Initial pattern/blind candidates are limited to the first 24 windows. A bounded sliding sync/header scan also supplies verified later positions when idle noise triggered acquisition early; it retains the original audio and uses CRC-checked timed completion without cutting off reception on a failed probe.
- **Chase second-choice retry**: flip up to six weak symbols to runner-up decisions. Standard requires CRC. Legacy retries must agree with the original observations and confidence values, not merely the modified hypothesis.
- **Anti-miscorrection gates** (Legacy profile): repaired headers, erasure decodes, inferred lengths, and Chase trials pass `reencode_agreement` (overall agreement and high-confidence disagreement checks). These remain heuristics, not a checksum. Standard checks CRC inside each attempt; Paranoid relies on TransferRx's validator. Final analysis compares successful classifiers using their own codeword agreement; an exact codeword ends the search. Arbitrary short prefixes cannot explain a much longer Standard/Legacy reception.
- **Length lock**: a zero-correction, high-confidence header plus matching preamble/pilot establishes the frame length, including after pilot-derived EQ. The lock persists across final-analysis offsets. Legacy mid-reception trials require a lock or a payload validator; Standard's built-in CRC validates inferred-length attempts too.
- **Damaged late headers**: a complete preamble/pilot match (raw or template/EQ) preserves a candidate and a bounded maximum-frame recording budget even if the length header is damaged. Sync-only candidates do not establish length locks or suspend later header scans. CRC still gates delivery, including when a bad frame precedes a valid one without a reset.
- **Receiver compute**: `fft.rs` reuses one replaceable plan/Hann/buffer/scratch workspace per thread; template matching precomputes fixed amplitudes and prefix norms. Both have bit-identical reference tests. Reed–Solomon shares one fixed 64 KiB `GF_PRODUCTS` table across field arithmetic and syndromes, shares initial syndromes across hard/erasure retries through a borrowed `PreparedBlock`, and initializes encoder-only generator polynomials lazily. `gf_mul` selects the second operand's table row to keep constant-factor polynomial loops localized. Exhaustive field-product checks use both the original log/exp formula and independent carry-less multiplication modulo 0x11d. The error locator reserves two `ecc_length + 1` buffers, then swaps/scales/adds in place; after any swap the current locator is at least as long as the previous one, so right-aligned XOR needs no resize or temporary polynomial. Original-loop comparisons cover every parity/erasure budget, zero/constant/random syndromes, and shifted single-impulse inputs; end-to-end reference decoding uses the old locator. `frame_geometry_allows` skips retries only when the existing byte-count/slop rules make success impossible. `examples/receiver_latency.rs` measures native Standard or `--transfer` 2048-sample callbacks and modeled queue debt; do not infer hard real-time behavior from average throughput, as background finalization can still cause long stalls.
- **Template dot products**: `NoteAmplitudeTemplates` stores four vowels side by side at each bin. `template_dots` uses NEON only when enabled on AArch64; other targets use the directly tested portable path. SIMD lanes are independent vowels, with separate multiply/add and the original increasing-bin accumulation order (no fused operations or horizontal reassociation). All 20 notes × four vowels remain eligible. Tests check every amplitude/prefix norm, all classification fields for mixtures and partial bands, and native/portable dot bits under cancellation, extreme scales, and unequal slice lengths. The small unsafe load/store block is bounded by four-element arrays and guarded by a compile-time vowel-count assertion and target feature cfg.
- **Recording deadline rollover**: after a failed maximum-recording analysis, retain `HEADER_PROBE_WINDOWS` (50 slots / three seconds) and reacquire from that overlap. This preserves a real preamble/header that arrived just before a noise acquisition's deadline. Keep the previous RMS estimate so following silence can release the lock. The recording deadline resets to a bounded size; failed attempts remain available to soft combining, and overlap never counts as a successful delivery.
- **Failure-only retry reuse**: `FailedPayloadCache` retains at most one pre-gate failed payload per length for an analysis (or standalone symbol-stream decode). `trial_decode` also shares a fresh cache across one speculative end-marker probe's classifier rungs; never retain it across probes, appends, or recordings. Keys compare the full body bytes, profile, length, and ordered erasure positions. Header-only Chase flips and identical classifier/alignment results can reuse deterministic RS/built-in-integrity failures; profile-valid bodies and header/agreement or caller-validator rejections are not cached, so changed confidence or approval still gets evaluated. A profile-valid result prevents caching even if the external predicate rejects it. Cached/uncached reference comparisons cover all profiles and lengths; targeted tests preserve payload/erasure recovery, Legacy gates, and stateful-validator retries. Probe-level comparisons also require identical payload/endpoints, observations and length-search counts, bounded storage, and strictly fewer repeated corrections in aggregate.
- **Erasure ordering reuse**: `PreparedByteErasures` lazily sorts weak-byte confidences once per fixed symbol hypothesis, then filters the same stable ordering by each candidate body's length and erasure budget. Its borrowed input cannot change, storage is capped at 255 positions, and a new Chase hypothesis creates a fresh view. Clean hard decoding does no sorting. Reference comparisons cover every 0–255-byte prefix and parity budget, with missing values, ties, threshold edges, NaNs, and infinities; tests also check lazy allocation and changed-hypothesis behavior.
- **RS prefix reuse**: `reed_solomon::PrefixDecoder` borrows the largest candidate body for one fixed hypothesis. Its first actual request uses ordinary syndrome evaluation; only a second request allocates prefix rows, and failure-cache hits do not trigger requests. Each needed root is evaluated once across the immutable body (at most 255 roots × 255 bytes; current profiles need at most 127 roots). `PreparedBlock` owns its extracted syndromes and still independently rechecks corrected codewords. Tests compare every valid length/parity pair, all-profile-length hard/erasure outcomes, lazy allocation, bounds, and exact row-work counts.
- **Per-alignment spectra**: `AlignedSpectra` borrows one immutable recording slice at a fixed sample offset. Header probes, pilot EQ/calibration, trial decodes, and final-analysis classifier retries share each window's FFT. The FFT remains full-size; the cache retains the first `RETAINED_SPECTRUM_BINS` (currently 194), covering F2 and the harmonic ceiling plus rounding/neighbor bins. Only one alignment is retained, never a cross-recording cache. Original uncached helpers remain under `cfg(test)` for bit-identical classification, EQ, calibration, and window-boundary comparisons at both sample rates.
- **Trailing-silence finalize**: Paranoid uses four relative-silence windows; Standard uses six. Normalized, DC-rejected autocorrelation vetoes silence for quiet periodic notes, including after denoising. Both 8 kHz and 48 kHz test a two-second, 40 dB phrase dip and a missing end preamble followed by silence.
- **Payload validator hook** (`Decoder::set_payload_validator`): TransferRx installs its allocation-free CRC predicate inside each hard/erasure, alternate-length, and Chase attempt. Rejection must continue the retry ladder, not filter only its final result: a hard-RS miscorrection can otherwise hide a correct erasure decode. `decode_symbol_stream_validated` supplies the same gate for merged streams. Tests cover erasure and Chase recovery after bad-CRC hard results, wrong-length prefixes, soft combining, and preservation of Standard CRC and length locks. Failed mid-reception trials keep receiving instead of splitting the copy.
- **Soft-combining alignment**: TransferRx aligns harvested attempts to the first by maximal symbol agreement over ±6 shifts before majority voting (attempts can be harvested on slightly different grids), and votes over the full reference length. Both speculative trials and final analysis retain only start-anchored observations (recorded start hints or exact preamble matches). An unanchored trial still runs the normal integrity-checked decode ladder, but cannot publish/overwrite a combining reference or increment the failed-copy count. Prefixes ending before a known anchor's data are not sliced. Regressions feed actual background with a late end-shaped fragment before complementary failed symbol copies: a spurious short reference previously prevented recovery. Note: solo decoding is now strong enough (erasures + Chase + brute-forced lengths + CRC-validated retry) that white noise cannot separate solo-fail from combine-pass; the voting mechanism is unit-tested with injected confident errors and shifts.
- **Combining lifecycle and bounds**: `AttemptCombiner` stores the first reference and per-position vowel counts/max confidences, not every failed stream. Align each new copy once; preserve the old shift/tie rules, majority decisions, confidence margins, and all copy contributions. `Decoder::take_last_attempt` transfers each observation once; solo delivery also consumes its observation. Clear the combiner only on CRC-verified solo/combined delivery, preserving decoder-buffered audio and the cumulative `attempts()` UI counter. This is not deduplication, nor automatic grouping of unrelated transfers before delivery. Full-history reference tests cover every vote/decision at each prefix, shifts, unequal lengths, ties, abstentions, and nonfinite confidence values; 4,096 copies retain fixed storage. Regressions cover stale replay, a short old reference blocking a longer next message, failed retries retaining votes, and buffered sequential/repeated payloads.
- **Block completion timing**: `clock_probe_shift` can postpone a slow frame's primary probe or add an earlier fast-frame probe only with a locally intact tracked header and clear, consistently moving guards after acquisition. Both measured halves must agree in direction and differ by at most half the measured drift (also capped at half the guard-search radius), rejecting settling transients on nominal clocks. Signed shifts stay within `clock_slack_windows`. The original worst-case fallback remains unchanged; fast frames retain their nominal deadline too. Missing/ambiguous evidence keeps nominal timing. Timing is not a payload validator. Tests cover maximum frames, gain invariance, wrong-length rejection, bounded shifts, and speedups/slowdowns after the header.
- **Noisy guard feedback**: block `AlignedSpectra::clocked` blends each supported guard step equally with the held period, then updates the period with weight 0.1. Missing evidence holds the period unchanged. These convex updates retain the original ±2.5 ms bounds and leave the entire current 50 ms voice before the next boundary. StreamRx's nominal voiced fallback and 0.05 smoothing remain unchanged. The combined-channel matrix covers 64 cases across 1/17/64/140-byte payloads, ascending/wide-leap/shuffled-detuned/Giant Steps contours, ±2% clocks, noisy phone, and tilt + RNNoise; no notes or audio samples are changed by timing recovery.
- **Quiet-tail completion**: four windows below 60% of recent voice RMS can prompt `analyze(false)` when an unambiguous retained length's earliest bounded body could fit. Without any retained length evidence, a fully verified sync candidate may instead prompt analysis after three quiet windows (a 180 ms inter-song gap), once a minimum body could fit. `can_probe_sync_only_tail` never supplies a length or overrides known/conflicting hints; a Listening lock alone is insufficient. Both paths require Standard CRC or an explicit validator and share the four-probe per-recording budget. Clear run/budget on reset, reacquisition, and delivery. Failure preserves audio and resumes scans, never finalizes or changes the strict RMS/periodicity gate. Tests preserve incomplete 40 dB quiet phrases with intact/damaged headers, require later exact delivery, and cover integrity, conflicts, earliest fit, budget, and lifecycle.
- **Delivery alignment context**: `finish_frame` retains at most two whole slots immediately before the successful voiced endpoint, separately from the unchanged exact lookahead buffer. Only CRC/caller-validated profiles retain this context. Never replay it through Listening measurements or preview; prepend it once to contiguous history at the next acquisition and include it in recorded counts/preamble indexing. Drop it when history slides or clears on silence, and on reset. The 16 continuous phone/denoiser cases cover four changing-clock melodies, maximum then quieter short frames, repeated payloads, zero/180 ms gaps, and a missing first marker in both profiles. Unit tests verify exact sample bits, constant bounds, one-time use, unchanged unread audio, header positions, and expiration.
- **Strict-silence probe ordering**: Paranoid's preview/end-stream skip must run after the bounded quiet completion probe, otherwise a truly silent three-slot gap bypasses sync-only recovery. Leave fourth-slot strict finalization above the probe unchanged. A failed third-slot attempt retains the full recording and does not classify silence into preview/recent streams. Native tests at both rates cover a damaged header/missing marker before a different next melody, caller rejection, intact-header timing, exact preview/history preservation, and fourth-slot release. The real worker browser test drains body + two silent slots with no delivery, then requires the first payload after exactly one more slot before feeding the next sender.
- **Verified clock priority**: the phased probe retains one `ClockHint` (lowest clear-guard score) from its locally verified non-nominal clock estimates. `try_clock_hint` may try that phase once before ordinary analysis, only with matching unambiguous length evidence and no earlier retained sync/header candidate. Recheck the current tracked header and require Standard CRC or an explicit validator; never use the shortcut for unchecked Legacy/Paranoid. A success carries its own sample endpoint through `finish_frame` and publishes an anchored observation. Failure changes neither recording/hints nor combining observations and does not consume any of the original 32 nominal offsets or 32 clock-fallback trials. Thus an analysis has at most one priority grid plus the original fallback budget. Clear the hint on delivery, reset, and reacquisition/rollover. Tests compare failed-search grids/observations with the no-hint path and cover local evidence, conflicts, earlier senders, incomplete data, validator rejection, bad CRC, lifecycle, and zero nominal grids for supported slow-clock success. Synthesis and integrity policy are unchanged.
- **Block delivery lookahead**: `DecodedFrame` carries the successful candidate's payload and final voiced-window sample endpoint on its own nominal/clocked grid. Both trial and final success use `finish_frame` to prepend the exact recorded suffix to unread callback audio, then clear acquisition/hint state. Never assume an intact end marker or discard another sender's already-recorded preamble. Failed probes retain their recording unchanged, and `last_attempt` remains available for the existing combining lifecycle. - **StreamRx fuzzy lock**: streaming preamble accepts exact, 3-of-4, or structural centroid matches — fuzzy paths gated by all four windows standing ≥3× above a slow-rising/fast-falling ambient noise floor (absolute 1e-4 on cold start). - **StreamRx quiet phrases**: relative-RMS silence candidates use the block decoder's normalized, DC-rejected `has_voiced_periodicity` veto. - **Transfer profile** (`src/transfer.rs`, for API-key-style secrets): CRC-32 inside the payload makes RS miscorrection an explicit failure (correctness, not security — encryption deliberately out of scope, same-room threat model); `EccProfile::Paranoid` = ~100% parity with brute-forced length when the weak 3-byte header is corrupted; `TransferRx` majority-votes symbols across repeated receptions, demoting contested positions to confidence-margin so they become RS erasures. ## Conventions

- Short echo timing retains the original 8→24-slot estimate first. Only recordings shorter than `8 * 24 * (SYMBOL_TOTAL_SAMPLES + CLOCK_RADIUS)` may try 8→16, 4→12, then 4→8 when earlier estimates reject. Do not relax correlation, half-agreement, drift bounds, sync/header or integrity checks; only one supported period enters the existing 32-phase search. Core tests cover both rates and following melodies; the 48 kHz matrix spans every 1–16-byte length.
- Exact zero RMS counts as receiving silence even before the level EMA initializes. Pilot collection and profile-specific silence counts remain unchanged. Below the sync/header minimum, release to Listening without fabricating a failed-copy observation or discarding unread samples. The focused regression preserves the pilot interval, both initialized/uninitialized levels, all profiles, and bit-exact queued audio for the next song.

- Audio is `f32` samples at 48 kHz (mono)
- Internal synthesis uses `f64` for precision, casts to `f32` at output
- Volume is `u8` 0..=100
- Max payload 140 bytes
- Tests use deterministic LCG PRNG (no randomness)
